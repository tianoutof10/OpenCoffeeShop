# Translation contributor guide

## English is the source of truth

Use stable, feature-scoped tokens in `src/i18n/en/*.ts`, such as
`library.action.unfavorite` or `brew.stage.reason.timeLimitReached`.
Keys describe meaning, not exact wording. Editing English normally does not rename
the key. A materially different meaning should have a new key.

Translate full messages with named placeholders. Do not assemble prose from
individual translated words. Reuse common tokens only when their meanings and
grammatical contexts really are identical. Names, notes, descriptions and stages
authored by users stay as written. Raw error messages returned by Decaid remain
verbatim; Bestpresso-generated error wrappers are translated.

## Adding a language

French, Italian, Traditional Chinese and Simplified Chinese currently have partial
Streamline-derived seed catalogs. See [source mapping and pending work](localisation-streamline.md).
Keep uncertain messages absent so the English fallback remains readable; blank
fields for the writing pass live in `localisation-pending.json`, not runtime files.

1. Create `src/i18n/<code>/index.ts` and feature files, following German's layout.
   Export a catalog satisfying `Translation<EnglishCatalog>`. Partial catalogs
   are supported; leave missing keys absent, not empty.
2. Add one entry to `src/i18n/registry.ts`: native name, default locale, direction,
   and a dynamic import returning the catalog.
3. Run `npm run i18n:check`, `npm run i18n:report`, tests and build.
4. Review the translated interface and acknowledge the reviewed keys as below.

No Settings, preference normalizer, or test-language list needs editing. The
registry drives all three. English is bundled as a guaranteed fallback; other
catalogs load on demand. Failed loads leave the UI usable in English, preserve the
selected preference, and may be retried by selecting/saving that language again.
Late loads never change the user's newer language choice.

An RTL entry sets the document direction, but that alone is not RTL certification:
review physical left/right styles, charts, navigation and touch controls before
shipping an RTL language.

## English updates and review status

`src/i18n/reviewed/<code>.json` stores the English source and translation as they
were explicitly acknowledged. It is development metadata, not shipped in the app.

- **Current:** both match the acknowledged revisions.
- **Needs review:** the English or translated wording changed, or has no review baseline.
- **Missing:** no translation; runtime uses English.

A source snapshot acts as the revision fingerprint and lets the report show the
previous and current English. Renaming/removing a source key surfaces obsolete
translation keys as validation errors. Reports never update review records.

After actually reviewing particular entries:

```sh
npm run i18n:review -- de common.metric.flow settings.action.save
npm run i18n:report
```

For an initial catalog baseline, or a deliberate review of an entire catalog:

```sh
npm run i18n:review -- de --all
```

The initial German baseline inherits PR84's supplied translations. “Current”
tracks revisions; it is not a claim that a native speaker has proofread every
phrase. Do not run `--all` merely to clear a report.

## Validation and CI

`npm run i18n:check` validates every registered catalog, not just German:

- Unknown/obsolete keys and empty supplied messages.
- Placeholder parity in each supplied plural branch, including markers such as
  `%ICON%`. It does not compare only the union of all plural placeholders.
- Required cardinal plural categories for the locale.
- New literal JSX interface text and accessibility labels.
- Potential unused source tokens, reported for manual review because dynamic
  key mappings can make static analysis incomplete.

Missing translations and pending reviews are coverage work, not build failures.
Malformed messages fail validation. Supplied plural entries must cover the locale's
categories (`zero`, `one`, `two`, `few`, `many`, `other`, as applicable).
`other` is always required. A wholly missing plural entry falls back to English
grammar as well as English wording.

Literal exceptions in `interface-literals.json` are narrowly scoped and require
a reason: units, brand names and icon glyphs. The scan is a guardrail, not proof
that every string assembled in application logic is translated.

CI runs validation, generates a coverage report artifact, runs the regression
suite and builds the app. Locally, `npm run i18n:report` updates
`docs/translation-coverage.md`; commit the report when changing catalogs.

## Numbers, units, dates and input

Keep numbers numeric in models, history and API requests. Localize only the
presentation. Regional preferences are retained when compatible with the selected
language: German in Switzerland and Germany need not share separators.

- `formatDecimal(value, digits)`: fixed precision, no grouping; preserves existing
  measurement rounding and uses Intl for punctuation and digits.
- `formatNumber(value, options)`: locale-aware numbers, with grouping if requested.
- `localizeDecimalText(value)`: bridge for legacy canonical numeric model strings
  and numeric ratios only. Never pass arbitrary prose, identifiers or already
  localized strings.
- `dateFormatter(options)`: localized dates. Existing temperature-unit and
  12/24-hour preferences remain independent.
- `parseLocalizedNumber(text, locale?)`: strict ungrouped input; supports the
  locale's digits and decimal separator, rejects ambiguous grouped input and
  non-finite values. It must never parse stored/API values.
- The adjustment keypad keeps canonical digits and a dot internally. Its labels
  are localized; its saved values and range checks are unchanged.

Do not use decimal-character replacement as a general number-formatting strategy.
Do not silently strip thousands separators from an editable measurement.

## History and stage reasons

Generated shot/stage labels carry a fallback identifier and are translated during
rendering. Stored user names are not translated. Existing generated labels are
repaired only when the shot-time recipe/signature proves there was no authored
name; uncertain legacy names are preserved.

Stage inference now supplies structured conditions (reason code, sensor,
comparison and threshold) alongside its existing source and advance/stop kind.
The compatibility English label remains for older consumers; display does not
depend on its exact wording. Old cached English evidence is parsed in one legacy
adapter without re-running or strengthening its conclusions.

Combined reasons use localized disjunctions and a complete “conditions reached”
template, allowing the verb before or after the list. Separators remain visually
muted. No string-suffix trimming is used.

This does not change exit detection or implement an unconfirmed Decaid API.
Once Decaid's event schema is agreed, its adapter can populate the same condition
structure while preserving provenance and actual available timing. A generic
firmware advance must not be upgraded into a definitive threshold reason.

## Browser checks

Check English and each supplied language on phone/tablet layouts, offline cached
history, changes through the real Settings selector, and a fresh session where
the language chunk fails to load. Use `?i18n-pseudo` for accented, expanded labels
that reveal untranslated text and constrained layouts.

Tests cover regional decimals, Arabic/Persian digits, Arabic plural categories,
missing entries, source-review changes, literal auditing, cache compatibility,
and lazy-load failure/retry/races. A fixture catalog is not a shipped language.
